# Three-point SDP bound for the N = 8 Thomson problem — scripts and data

Companion to `../N8-Thomson-Blueprint.md` §12 (read that first) and to the Lean modules
`../Thomson/ThreePoint/{BV,Bound,Toolkit,MinPoly,CertData,Linear,Tasks}.lean` (umbrella `../Thomson8.lean`), which
formalises the proof: `thomson_eight_lower` is proved there; the only `sorry`s are the
**Tasks** in `Thomson/ThreePoint/Tasks.lean` (eight leaves: 1a `det ≠ 0`, 1b pivot enclosure, 1c two redundant rows, 2 PSD, 4 pair, 5a/5b triangle; Tasks 0, 3, 6 are proved).
**The certificate is defined implicitly** (`Linear.lean`: `pivots := pivotMatrix⁻¹ *ᵥ pivotRhs`, data tables in `CertData.lean` generated by `task1_emit_lean.py` from `task1_design.json`), because its exact closed forms have 15 000-digit coefficients.  Bachoc–Vallentin positivity is fully proved.
`Thomson/` is a standalone Lake project: `lake exe cache get && lake build`.  **Start from the Lean file**: it states exactly what must be supplied.  All scripts need a venv with
`numpy scipy mpmath sympy cvxpy clarabel` (`python3 -m venv venv && venv/bin/pip install ...`).
They were written for a session scratchpad; paths inside them point there — set `sys.path`/cwd to
this folder and they run unchanged otherwise.

| file | purpose |
|---|---|
| `bv.py` | Bachoc–Vallentin matrices `S_k^3(u,v,t)` for `S^2` (Chebyshev inner polynomial), with a numerical PSD check |
| `sdp3b.py` | three-point SDP, `λ = 0` form, grid discretised, with post-hoc fine-grid verification |
| `sdp3g.py` | the `λ` form (triangle polynomial tracks the potential) — the form that is sharp |
| `sharp.py`, `sharp_restricted.py` | sharpness tests: antiprism pairs/triangles added as exact constraints; restricted Legendre support |
| `force3.py`, `bootloop.py` | forced-pair bootstrap (range shrinking); converges at `t ∈ [−0.937, 0.44]` for `λ=0` |
| `check3.py`, `check_lam2.py` | numerical verification of the exact decomposition identities (all terms ≥ 0, residual 1e-13) |
| `kernels.py` | rank-1 structure of `Σ_{ijl} S_k(antiprism)` and complementary slackness |
| `certificate_numerical.json` | **the sharp certificate**: `a0, a1, λ, F_0..F_5`, kernel vectors, antiprism data |
| `exact_kernels.py` → `kernel_vectors_exact.json` | exact kernel vectors `v_k(u)` — rational functions of `u`, no `√2` (§12.5 step 1) |
| `project_certificate.py` | first look at projecting the SDP-optimal certificate onto the kernel constraints |
| `gonogo.py` → `certificate_tight.json` | **go/no-go**: impose exact tightness at the antiprism as linear constraints, maximise PSD margin — passed, `μ* = 2.5e−3` |
| `gonogo2.py` / `gonogo3.py` / `gonogo4.py` | fixed PSD margin + weighted inequality slack; + cutting planes; + **Hessian LMIs at the touching points** (essential — see §12) |
| `certificate_pd.json` (+`_hp`), `certificate_etamax.json` (+`_hp`) | valid tight certificates with PD Hessians; `INVALID_eta1e-3_*` are **invalid** (η too large, ε<0), kept only as a record — see §12 |
| `verify_tight.py <cert> <n/axis>` | dense-grid verification: bound, kernels, PSD margins, pair/triangle inequalities, tightness |
| `hp_project.py <cert>` → `certificate_hp.json` (**scratch — always overwritten; load a named `*_hp.json` instead**) | 50-digit projection onto the exact tightness space (residual `~1e−17`) + high-precision checks |
| `hessians.py <hp cert>` | Hessians of the triangle slack at the five touching types, `P''` at the four distances |
| `lp.py`, `cert.py`, `verify.py`, `impossible2.py` | two-point LP, and the exact rational certificate proving the LP method is capped (§10) |
| `tumanov.py`, `analytic.py`, `hessian.py`, `families_exact.py`, `three_optima.py` | §9 and §11 computations |
| `task1_exact.py`, `task1_exact_polybasis.py` → `task1_rows*.pkl` | **Task 1**: exact arithmetic in the degree-192 field `K = ℚ(√2,u*,r,s₂,s₄)`; the 29 tightness rows as exact `K`-linear functionals (normalised / inverse-free kernel bases) |
| `task1_solve.py` → `task1_exact_solution.pkl` | exact 24×24 solve over `K` (4608×4608 rational system, FLINT): all 29 rows to `3e−38`, **but coefficients of 15 846 digits** — hence the implicit design |
| `task1_design.py`, `task1_design2.py` → `task1_design.json` | **the implicit design**: 26 rows (duplicates removed) of rank 24; bound row kept, `pairA_val` and `triFDN_dv` dropped; `a0,a1,λ` rational; scaled inverse-free bases (`H'_k` min eigenvalues ≥ 5.9e−4); 50-digit pivots (`pivots_num`, 22 digits), margins |
| `task1_leanform.py` | the same system in the chord-variable form used by `Linear.lean` (cond `1.1e5`, `‖M‖∞ 132`, `‖N‖∞ 3.9e3`, `‖I−NM‖∞ 5e−12` with the 17-digit rational `approx_inverse` stored in `task1_design.json`; residual at `pivotsNum` `2e−21`) |
| `task1_emit_lean.py` → `../Thomson/ThreePoint/CertData.lean` | renders the Lean data tables (`Bpoly`, `Hfix`, `slot`, `pivotsNum`) — regenerate after any change of design |
| `task1_emit.py`, `task1_split2.py` | superseded (explicit LDLᵀ rendering; first split experiment) |
